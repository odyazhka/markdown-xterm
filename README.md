ниже описание от клода

Markdown прямо в терминале. Патч для xterm 411, который на лету превращает markdown в цвет, жирный, курсив, таблицы и списки. Вывод нейронок (ollama и др.), cat README.md, заметки: всё выглядит красиво без внешних программ и пайпов.

Что умеет
Markdown	Как выглядит
# ###### заголовки шести цветов, жирным, без #
**жирный**, __жирный__, *курсив*, _курсив_, ***оба***, ~~зачёркнутый~~	соответствующий стиль
`код` (и `` ` ``)	ярко-голубой, внутри ничего не форматируется
``` и ~~~ блоки кода	голубой, сами ограждения скрыты; вложенные блоки (```python внутри ```markdown) работают
таблицы | a | b |	рамка из линий, выравнивание колонок (:---, :---:, ---:), заголовок жирным, ячейки переносятся под ширину терминала, внутри ячеек работает форматирование и <br>
- , * , + списки	зелёная точка, вложенность (• ◦ ▪), перенос с отступом
1. нумерованные, - [ ] / - [x]	номера и чекбоксы ☐ ☑
> цитата, >> вложенная	приглушённый курсив с полоской слева
[текст](url), ![alt](url), <https://...>, голые URL	подчёркнутая ссылка, адрес приглушённо
---	линия на всю ширину терминала
\*, \_, ...	экранирование

Длинные абзацы переносятся по словам под реальную ширину окна. Полноэкранные программы (vim, less, htop) конвертер не трогает. Строки со своими цветами (ls --color, серый «Thinking...») обрабатываются: цвета сохраняются, markdown внутри конвертируется. Строки, где программа двигает курсор (прогресс-бары, редакторы), остаются как есть.
Быстрая сборка

Нужны: cargo (Rust), gcc, make, curl, patch и dev-пакеты X11:
sh

# Void
sudo xbps-install -S base-devel rust cargo curl patch libXaw-devel libXt-devel libXft-devel libXmu-devel libXpm-devel libXext-devel libX11-devel ncurses-devel
# Debian / Ubuntu
sudo apt install build-essential cargo curl patch libxaw7-dev libxt-dev libxft-dev libxmu-dev libxpm-dev libxext-dev libx11-dev libncurses-dev
# Fedora
sudo dnf install gcc make cargo curl patch libXaw-devel libXt-devel libXft-devel libXmu-devel libXpm-devel libXext-devel libX11-devel ncurses-devel
# Arch
sudo pacman -S --needed base-devel rust curl patch libxaw libxt libxft libxmu libxpm libxext libx11 ncurses

Дальше одна команда:
sh

git clone https://github.com/<твой-ник>/mdterm-bridge.git
cd mdterm-bridge
./build.sh

Скрипт соберёт Rust-библиотеку, скачает исходники xterm 411, наложит патч и соберёт xterm. Готовый бинарник: build/xterm-411/xterm.
sh

build/xterm-411/xterm                                  # обычный запуск
build/xterm-411/xterm -e sh examples/demo.sh           # показать все возможности
MDTERM=0 build/xterm-411/xterm                         # конвертер выключен

    Не клади проект в путь с пробелами: configure не любит их в LIBS.

Ручная сборка (если хочешь по шагам)
sh

# 1. Rust-библиотека -> target/release/libmdterm_bridge.a
cargo build --release

# 2. исходники xterm 411 (нужна именно эта версия)
curl -L https://github.com/ThomasDickey/xterm-snapshots/archive/refs/tags/xterm-411.tar.gz | tar xz
mv xterm-snapshots-xterm-411 xterm-411
cd xterm-411

# 3. заголовок + патч
cp ../mdterm_bridge.h .
patch -p1 < ../xterm-411-mdterm.patch

# 4. сборка с линковкой библиотеки
LIBS="-L$(realpath ../target/release) -lmdterm_bridge -lpthread -ldl -lm" ./configure
make -j4
./xterm

Патч накладывается один раз на чистые исходники. Если поменялся сам патч, удали xterm-411 и начни с шага 2 (./build.sh делает это сам).
Изменил src/lib.rs, как пересобрать

make не замечает, что поменялась .a-библиотека, поэтому бинарник нужно удалить, иначе получишь старую версию:
sh

cargo build --release
cd build/xterm-411
rm -f xterm
make

Или просто запусти ./build.sh ещё раз.
Поменять цвета

Цвета заголовков: функция heading_style в src/lib.rs, цвета кода, ссылок и т. п.: константы в начале файла. Это обычные ANSI SGR-коды (\x1b[1;35m = жирный розовый, \x1b[96m = яркий голубой).
Как это устроено

xterm читает вывод программы из pty в readPtyData() (ptydata.c). Патч вставляет туда фильтр: сырые байты идут в Rust (mdterm_feed), который держит недописанную строку до \n, конвертирует markdown в ANSI-последовательности и отдаёт обратно. Дальше xterm видит обычный цветной текст.

    Строка показывается целиком по \n, чтобы **жир + ный** не разорвались.
    Программы вроде ollama сами переносят строки, вставляя ESC[nD ESC[K («шаг назад, стереть, перенос»). Конвертер узнаёт такие мягкие переносы, склеивает строки обратно (поэтому **жирный** и строки таблиц не рвутся) и сам переносит текст по словам под ширину окна.
    Между токенами ollama шлёт ESC[?25l ESC[?25h; это пустая пара, её выбрасывают.
    Недописанная строка не висит вечно. Таймаут адаптивный:
        40 мс для приглашения шелла ($ , user@host:~# , >>> ), эха набираемых символов и строк с управляющими кодами;
        60 секунд, пока идёт медленный поток (нейросеть выдаёт строки по одной раз в несколько секунд): пауза модели посреди строки не портит форматирование;
        2 секунды во всех остальных случаях.
    Таблица накапливается до конца и рисуется целиком. Если поток остановился, она всё равно будет нарисована по таймауту.
    В alt-screen (vim, less…) конвертер отключается.
    Если результат не влез в буфер xterm, остаток ставится в очередь и досылается.

Настройки через переменные окружения: MDTERM=0 (выключить), MDTERM_HOLD_MS (обычный таймаут, по умолчанию 2000), MDTERM_STREAM_MS (для потока, по умолчанию 60000), MDTERM_DEBUG=файл (лог).
Ограничения

    Конвертация построчная, без полноценного CommonMark: не поддерживаются сноски, определения, HTML-блоки, формулы, вложенные списки внутри цитат.
    Незакрытый блок ``` красит вывод в голубой до следующего ``` (после возврата к приглашению шелла состояние сбрасывается).
    Патч сделан только под xterm 411. На другие версии может лечь с ошибками.
    Сообщение «□□» вместо иероглифов: шрифт терминала их не содержит (например, Qwen иногда вставляет китайские слова). Поставь шрифт с CJK (Noto Sans CJK) или попроси модель отвечать только по-русски.

Если что-то не конвертируется: отладка

Запусти терминал с логом и повтори проблемную команду:
sh

MDTERM_DEBUG=/tmp/md.log build/xterm-411/xterm
# ...запусти в нём программу, потом:
head -c 4000 /tmp/md.log

IN — что программа отправила (управляющие байты как \xNN, \r, \n), OUT — что ушло на экран, FLUSH — строка, показанная по таймауту.

Записанный лог можно проиграть обратно в патченом терминале и увидеть ровно то, что видел ты (приложи md.log к issue):
sh

build/xterm-411/xterm -e python3 tools/replay.py /tmp/md.log
